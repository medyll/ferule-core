### 1.1 — TD-01: Asset management conventions

**File:** `structure.md`
**Problem:** No conventions for video files, images, or binary assets within applications.
**Risk:** Medium — apps will invent ad-hoc conventions.

- [x] Add `assets/` as optional app-root directory for binary media (images, video, audio)
- [x] Document supported formats: `.png`, `.jpg`, `.gif`, `.mp4`, `.webm`, `.svg`, `.mp3`, `.wav`
- [x] Add rule: assets referenced from markdown use relative paths
- [x] Add to `KNOWN_DIRS` in `check-structure.mjs`

**Effort:** 20 min

### 1.2 — TD-02: Cross-application dependency tracking

**File:** `structure.md`
**Problem:** No mechanism to track dependencies between applications.
**Risk:** Medium — changes may break dependent apps without warning.

- [x] Define `DEPENDENCIES.md` as optional app-root file
- [x] Document format: table with `App | Type | Notes` columns
- [x] Types: `required` (blocks operation), `optional` (enhanced features), `data` (consumes output)

### 1.3 — TD-03: Archive policy for old versions

**File:** `structure.md`
**Problem:** Old version folders accumulate with no lifecycle policy.
**Risk:** Low — workspace bloat over time.

- [x] Define archive policy: preserve all version folders indefinitely (they are historical record per §12)
- [x] Add guideline: `archives/` for rotation within a version, not for version folders themselves
